# Upload Bencher CI Job

## One-Line Goal

Upload benchmark JSON generated by `benchmark-effects` to Bencher Cloud after
correctness gates pass.

## Inputs

- case set: `benchmark-effects` `report.json`;
- audio shape: inherited from benchmark job;
- backend: scalar/SIMD labels from report metadata;
- third-party binaries: none at upload time;
- feature flags: not applicable.

## Command

```bash
rtk bencher run \
  --project "${BENCHER_PROJECT}" \
  --token "${BENCHER_API_TOKEN}" \
  --adapter json \
  --file "target/benchmarks/ci/${GITHUB_RUN_ID}/effects/report.json"
```

The exact adapter may change once the benchmark report schema is finalized.

## Output Policy

- output directory: no new benchmark output;
- preserved baseline: not applicable;
- artifacts: upload log and linked Bencher run URL;
- retention: GitHub Actions log and Bencher history.

## Pass/Fail Rule

Upload failures fail the scheduled benchmark workflow after benchmark
correctness has passed. Pull requests should not require Bencher credentials.

## Rerun Rule

Rerun upload only for the same immutable benchmark artifact. Do not rerun
benchmarks just to fix upload metadata unless the artifact is invalid.

## Failure Triage

- missing token: skip only on contexts that intentionally lack secrets;
- invalid JSON: fix benchmark report schema before upload;
- rejected metric: update adapter mapping and preserve failed artifact;
- Bencher outage: retry according to CI retry policy.

## Done When

- Upload consumes a stable `report.json`.
- Secret handling is documented.
- Failed uploads preserve enough metadata to replay from the same artifact.
